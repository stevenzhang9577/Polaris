# 批量论文总结与本地 Vault 目录

## 使用

在文献库的「论文库」页，点击「全选筛选结果」再点击「生成总结」。全选包含服务器上
符合当前筛选条件的全部页面；可以取消个别论文。改变筛选条件会清空选择。语义搜索只
选择返回的搜索结果，不会将它解释为整个文献库。

确认窗口显示选择数量、当前并发数和模型调用费用提示。默认跳过已有有效总结；取消
此选项会生成新历史版本，不会删除旧版本。创建时固定论文清单，后续导入不自动加入。
一次最多选择 50,000 篇。此限制是单次任务大小，不是文献库容量限制。

「设置 → 论文总结」可调整同时处理的论文数：1–10，默认 3。单篇生成与批量任务共用
当前用户的额度；降低额度不会中断已经启动的论文。并发数指处理中的论文，不是供应商
的 RPM/TPM 配额；仍可能遇到模型服务限流，需要降低并发并重试失败项。

「总结任务」显示等待、处理中、完成、跳过和失败数量，以及各篇获取全文、解析、生成、
同步工作区的阶段。暂停只停止领取下一篇；已经处理中的论文会完成。继续或重试不需要
重新选择论文。关闭弹窗不停止任务；Desktop 必须保持应用运行，退出后下次启动会恢复。

## 持久化与恢复

`summary_batches` 保存用户范围内的幂等请求凭据和选择快照；`summary_batch_items` 保存
每篇论文状态和生成版本 ID。HTTP 提交先事务落库再入队，投递失败不丢任务，启动和周期
对账会重投递。创建接口相同请求 ID/参数返回同一批；相同 ID/不同参数返回 409。

数据库租约限制同一用户的并行处理数，并保证同篇论文不由两个生成器同时处理。调度器
另有批次租约，防止跨 worker 重复调度。正常退出释放租约；异常退出等待最长 5 分钟租约
过期，再由对账任务恢复，期间进度可能暂时显示处理中。Desktop 对账周期为 15 分钟，
Server 为 10 分钟。已完成版本保留；模型请求中断可能需要重试并产生额外供应商费用。

路由：`GET/PUT /api/summary-settings`；
`POST/GET /api/libraries/{library_id}/summary-batches`；
`GET /api/libraries/{library_id}/summary-batches/{batch_id}`；
`POST .../{batch_id}/pause|resume|retry`。
批量接口仅库管理者可用，批次还需归属当前用户；不可访问对象统一返回 404。

## Obsidian 目录

「设置 → Obsidian Vault」先选择已有 Vault，再填写子目录名，例如 `008-Polaris`。
默认仍为 `Polaris`。预览路径确认后保存；不修改整个 Vault 或 `.obsidian`。

同 Vault 内更换目录会原子移动整个托管目录，保留同步基线、未同步编辑和冲突文件。
更换 Vault 会复制到新位置并保留原文件；目的目录已存在则拒绝覆盖。迁移失败会回退
配置和文件移动。更换前建议保留 Vault 的常规备份。
